# 아젤 연동 설정 가이드

아젤이 집 기기와 음악을 다루게 하는 방법이에요. 지금은 Home Assistant만 바로 쓸 수 있고, Apple Music과 HomeKit 단축어는 자리만 잡아 두었어요(기기 데몬 쪽 작업이 끝나면 채워요).
조사 내용과 선택 이유는 [INTEGRATIONS-research.md](INTEGRATIONS-research.md)에 있어요.

## 1. Home Assistant (공식 MCP 서버)

Home Assistant(HA)의 공식 "Model Context Protocol Server" 통합을 아젤의 사용자 지정 커넥터로 붙여요. 아젤은 그 서버가 알려 주는 도구로 집 기기를 켜고 끄고 상태를 읽어요.

### 준비물
- 켜져 있는 Home Assistant (최신 버전 권장). 아젤 게이트웨이가 닿는 주소여야 해요: Tailscale 주소(`http://100.64.x.x:8123`)나 HTTPS 주소. 인터넷에 그대로 공개하지 마세요.
- HA 관리자 계정(통합을 켜는 데만 써요).

### 순서
1. **통합 켜기**: HA에서 설정 → 기기 및 서비스 → 통합 추가 → "Model Context Protocol Server". 처음 켤 때 관리자 계정이 필요해요.
2. **전용 사용자 만들기**: 설정 → 사람 → 사용자에서 `azel` 같은 전용 사용자를 만들어요. 가능하면 관리자 권한을 주지 마세요. 아젤이 쓰는 토큰은 이 사용자의 권한을 그대로 가져요. (관리자가 아니면 MCP 서버가 안 되는지는 직접 확인해 주세요.)
3. **긴 수명 토큰 만들기**: `azel` 사용자로 로그인 → 프로필 → 보안 → "장기 액세스 토큰" → 만들기. 토큰은 **한 번만** 보이니 바로 다음 단계에 쓰세요. 채팅이나 메모, 커밋에 붙여 넣지 마세요.
4. **아젤에 서버 추가**: 아젤 앱 → 커넥터 → 서버 추가.
   - 이름: `ha` (영문, 숫자, `-`, `_`만)
   - 주소: `https://<HA 주소>/api/mcp` (주소 경로는 HA 통합 페이지에서 한 번 확인해 주세요)
   - 전송 방식: `http`
   - 비밀값: 3단계의 토큰. 토큰만 붙여 넣으면 `Authorization: Bearer …`로 보내요. 비밀값은 쓰기 전용이라 앱에서도 다시 볼 수 없어요.
   - 주소가 `http://`라면 Tailscale 주소(100.64.0.0/10)만 돼요. 그 밖에는 HTTPS가 필요해요.
5. **어떤 기기를 열어 줄지 정하기**: 설정 → 음성 어시스턴트 → "노출" 탭에서 아젤이 다룰 기기만 켜요. MCP 서버는 여기서 노출한 기기만 보여 줘요.
6. **도구 제한하기(권장)**: 서버가 주는 도구 중 필요한 것만 허용해요. 허용 목록(`allowed_tools`)은 도구 이름이나 `*` 패턴이고, 비워 두면 전부 허용돼요. 앱에는 아직 입력 칸이 없어서 게이트웨이에 직접 보내요. 토큰은 터미널에 쓰지 않고, 기존 값은 그대로 유지돼요.

   ```bash
   TOKEN=$(cat ~/.config/biseo/token)
   /usr/bin/curl --noproxy '*' -s -X PUT "http://<게이트웨이 주소>/v1/connectors" \
     -H "Authorization: Bearer $TOKEN" -H 'Content-Type: application/json' \
     -d '{"claude_ai":[],"custom":[{"name":"ha","url":"https://<HA 주소>/api/mcp","transport":"http","enabled":true,"allowed_tools":["GetLiveContext","HassTurnOn","HassTurnOff","HassLightSet"]}]}'
   ```

   이 예시는 `claude_ai`를 비워 보내므로 기존 claude.ai 커넥터 스위치는 기본값으로 돌아가요. 이미 바꿔 둔 게 있으면 `GET /v1/connectors` 결과를 그대로 가져와 `custom`만 고쳐 보내세요. 도구 이름은 HA 버전마다 다를 수 있으니, 처음에는 `allowed_tools`를 비운 채 아젤에게 "어떤 도구가 있어?"라고 물어 이름을 확인한 뒤 채우세요.
7. **확인**: "거실 불 켜 줘", "거실 온도가 몇 도야?"처럼 말해 보세요. 안 되면 비밀값이 들어갔는지(앱에서 "비밀값 있음"), 주소가 게이트웨이에서 닿는지부터 보세요.

### 꼭 지킬 것: 이런 기기는 노출하지 마세요
- **잠금장치(도어락), 차고문, 경보 장치**는 절대 노출하지 마세요. 음성이나 잘못 알아들은 말, 웹에서 읽은 글에 담긴 지시로 문이 열리면 안전 문제예요.
- 카메라, 개인 정보가 담긴 센서, 보일러·전기 히터처럼 켜 두면 위험한 기기도 처음에는 빼세요.
- 정말 필요하면 HA 쪽 자동화로 "확인 단계를 거치는" 스크립트만 노출하고, 아젤이 직접 풀지 못하게 하세요.
- 노출한 기기 목록은 가끔 다시 살펴보세요. 새로 추가한 기기는 자동으로 노출될 수 있어요.

### 문제가 생기면
- 토큰이 새었다면: HA 프로필 → 보안에서 그 토큰을 삭제하고 새로 만든 뒤 4단계의 비밀값을 다시 넣으세요(같은 이름에 다시 쓰면 덮어써요).
- 서버를 잠시 끄려면 앱에서 커넥터 스위치를 끄세요.
- 이 방식은 토큰을 직접 넣는 방식이에요. OAuth(브라우저 동의) 연결은 아직 지원하지 않아요.

## 2. Apple Music (Mac) — 자리만 잡아 둠

> 기기 데몬 세션이 채워요. 예정된 내용:
> - 도구 이름과 동작(재생, 일시정지, 다음 곡, 볼륨, 지금 재생 중인 곡)
> - macOS에서 한 번 눌러야 하는 권한(자동화: 데몬이 Music 앱을 제어)
> - 라이브러리에 있는 곡·재생목록만 이름으로 틀 수 있다는 제한
> - 문제 해결

## 3. HomeKit 단축어 — 자리만 잡아 둠

> 기기 데몬 세션이 채워요. 예정된 내용:
> - 장면마다 Mac의 단축어 앱에서 단축어를 하나씩 만들고, 처음에 한 번 직접 실행해 허용하기
> - 아젤이 부를 수 있는 단축어 이름 허용 목록(목록에 없는 이름은 실행하지 않아요)
> - 단축어는 켜기·끄기만 하고 상태를 읽어 오지는 못한다는 제한
> - 잠금장치·차고문·경보 장면은 만들지 않기
